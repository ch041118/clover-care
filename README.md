# CLover · 일상을 잇는 돌봄

어르신의 한마디를 돌봄 일정으로 연결하고, 사회복지사는 예외 상황을 조율하는 웹앱입니다. Expo 앱은 서버의 웹 화면을 열고 로그인 유지·푸시 알림·마이크를 담당합니다.

## 소스 다운로드 및 실행

```sh
git clone https://github.com/ch041118/clover-care.git
cd clover-care
npm ci
npm start
```

브라우저에서 http://localhost:3000/app/ 을 엽니다. 최초 관리자 생성 및 역할별 가입은 [계정 안내](docs/AUTH.md)를 참고하세요.

이 저장소는 소스 코드 공개용입니다. 원본 붓글씨 로고는 제외했으며, 공개 버전은 텍스트로 표시합니다. 실제 서비스 계정·개인 데이터·API 키·녹음 파일은 포함하지 않습니다. 음성 인식과 대화 모델은 별도로 연결해야 합니다.

최근 검증 범위와 제한은 [전체 점검 결과](docs/FULL-CHECK-2026-11-02.md)에 정리되어 있습니다. 해당 문서의 로컬 결과 파일과 화면 캡처는 공개 저장소에서 제외했습니다.

## 실무자·자체 피드백 반영

돌봄 비서에서 21개 조회 도구와 4개 변경안 도구를 사용합니다. 요양보호사는 주간 시간표로 본인 일정을 확인하며, 어르신은 오른쪽으로 넘기거나 큰 버튼을 눌러 시간표를 볼 수 있습니다. 음성 요청은 내용 확인 후 접수하고 확정 일정은 별도로 확인·변경 요청할 수 있습니다. SOS·119·응급 요청은 제공하지 않습니다.

## 웹 중심 앱 실행

- 웹: `npm start` → http://localhost:3000/app/
- 앱: `npm ci --prefix expo` 후 `npm run expo` → 앱에서 HTTPS 웹 주소 입력
- 외부 와이파이에서 접속: [HTTPS 서버 배포 안내](docs/DEPLOY.md)
- 실제 회원가입·로그인: [계정 안내](docs/AUTH.md)
- 앱 구조·HTTPS 연결·푸시 빌드: [Expo 안내](docs/EXPO.md)

웹 화면 변경은 서버에 반영하면 됩니다. Expo Go에서는 웹/로그인을 시험하고, 원격 푸시는 별도 개발 빌드와 FCM/APNs 설정이 필요합니다.

## 매일 저녁 안부 확인

매일 19시, 당일 앱 사용이 없으면 5분 간격으로 총 3회 안부를 묻습니다. 19:15까지 응답이 없으면 사회복지사 확인 대상으로 올립니다. **오늘의 안부**에서 시간·횟수와 처리 내역을 관리합니다. 실제 푸시에는 Firebase/APNs 설정이 필요합니다. [기능·연결·체험 안내](docs/WELLNESS.md)를 참고하세요.

## Android · iPhone 앱 버전

설치형 앱 프로젝트를 추가했습니다. 첫 실행에서 보호사가 사용자와 어르신을 연결하면, 이후에는 바로 마이크 화면으로 열립니다.

- Android 프로젝트: `android/`
- iPhone 프로젝트: `ios/App/App.xcodeproj`
- 앱 빌드와 설치 안내: [docs/MOBILE.md](docs/MOBILE.md)
- 공통 앱 번들: `npm ci` 후 `npm run sync:mobile`
- 앱 화면 미리보기: `npm start` 후 http://localhost:3000/mobile/

APK/IPA는 아직 생성되지 않았습니다. Android Studio/JDK/SDK 또는 Mac/Xcode 빌드 환경에서 설치 파일을 만들어야 합니다.

## 기존 웹 서버 실행

Node.js 22 이상이 필요합니다. 최초 실행 전 `npm ci`로 의존성을 설치합니다.

```powershell
npm start
```

- 관리 화면: http://localhost:3000
- 어르신 화면: http://localhost:3000/#elder/e1
- 테스트: `npm test`
- 저장 위치: `data/state.json` (최초 실행 시 가상 데이터 생성, 재시작해도 유지)

서버는 인증과 역할별 API 권한 검사를 적용하며 127.0.0.1에 바인딩합니다. 실제 휴대폰에는 HTTPS 배포 주소를 연결합니다. 역할 전환과 가상 사용자 선택은 별도의 기기 내 체험 모드에서만 제공합니다.

## 체험 순서

1. 관리 화면의 **요청 시연하기**에서 어르신, 서비스, 희망 일시를 선택합니다. 희망 일시를 비우면 최대한 빠른 시간을 찾습니다.
2. **보호사로 전환**한 뒤 배정된 보호사를 선택하고 요청을 열어 수락합니다.
3. 방문이 어려우면 **수행 불가**에서 사유를 입력합니다.
4. **복지사로 전환**하면 조율 목록에 나타납니다. **일정 직접 조율하기**로 보호사·일시·조율 내역을 입력합니다.
5. 재신청된 보호사가 수락하면 확정됩니다. 예정 종료 시간 이후에 완료할 수 있습니다.
6. 요청 상세에서 최초 신청, 수락, 불가 사유, 재조율 및 완료 이력을 확인합니다.
7. **어르신 관리**에서 마이크 화면을 엽니다. 실제 어르신 화면에는 역할 전환이나 회원가입 메뉴가 없습니다. 관리자 화면 복귀는 브라우저 뒤로 가기입니다.

## 구현한 흐름

`음성 해석 → 어르신 내용 확인 → 접수 → 자동 배정 / 수락 대기 → 보호사 수락 / 확정 → 돌봄 완료`

`배정 실패 또는 보호사 불가 사유 → 조율 필요 → 사회복지사 재신청 → 수락 대기`

- 등록 보호사의 서비스 종류·가능 요일·근무 시간·직선거리 5km 조건을 검사합니다.
- 희망 일시 이후의 가장 빠른 슬롯을 우선하고, 같은 슬롯이면 가까운 보호사를 선택합니다. 희망 시간이 없으면 현재 시각으로부터 최소 30분 후부터 탐색합니다.
- 15분 단위, 60분 돌봄, 앞뒤 30분 일정 여유, 7일 탐색 범위를 시연 기본값으로 사용합니다. 보호사와 어르신의 중복 예약을 모두 검사합니다.
- 후보가 없거나 음성 해석에 확인이 필요하면 자동 확정하지 않고 조율 대상으로 남깁니다.
- 짧은 시간 내 동일 어르신·동일 서비스의 반복 요청은 중복 접수를 막습니다.
- 보호사가 어르신 등록을 대신하는 양식, 보호사 가능 시간 편집, 이름·상태 검색, 완료 내역을 제공합니다.
- 마이크는 누르고 있는 동안 녹음하고 손을 떼면 전송합니다. 권한 요청 중 손을 뗀 경우 녹음하지 않습니다. 취소·화면 이동 시 녹음을 중단하고 최대 녹음 길이는 60초입니다.
- 어르신 화면이 열려 있으면 7초마다 상태를 확인하며 기기 음성 합성으로 안내합니다. 앱을 닫았을 때의 푸시는 아직 없습니다.

## 로컬 음성 인식 · LLM 연결

`.env.example`을 `.env`로 복사한 다음 설치된 서비스에 맞게 설정하고 서버를 재시작합니다.

```dotenv
STT_URL=http://127.0.0.1:8000/v1/audio/transcriptions
STT_MODEL=whisper-1
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_MODEL=your-installed-model
```

`STT_URL`은 직접 준비한 로컬 OpenAI 호환 음성 인식 서버입니다. multipart `file`, `model`, `language=ko`를 받고 `{ "text": "인식한 한국어" }`를 반환해야 합니다. 설치된 모델 이름에 맞게 `STT_MODEL`을 변경하세요. 한국어 및 브라우저가 만드는 WebM/MP4 파일 디코딩을 지원해야 합니다. 이 저장소는 음성 모델이나 서버를 설치하지 않습니다.

Ollama에는 JSON Schema 형식으로 서비스·희망 일시·확인 필요 여부를 요청합니다. 반환한 서비스와 날짜 형식을 서버에서 검증하고, 실제 배정은 결정적 일정 로직이 처리합니다. 음성 녹음 파일은 이 앱에서 디스크에 저장하지 않으며 전사문은 요청 이력에 저장합니다. STT 서버 자체의 저장 정책은 별도로 확인해야 합니다. 브라우저 클라우드 음성 인식으로 우회하지 않습니다.

현재 API 키, STT 서버, Ollama 모델이 제공되지 않았으므로 실제 음성 인식/해석 성공 여부는 검증하지 않았습니다. 미설정 상태의 마이크는 준비 중 안내를 표시하며 가짜 성공 처리를 하지 않습니다. 연결 상태 표시는 환경 변수 설정 여부이며 실제 건강 상태 검사 결과가 아닙니다.

## 네이버 연결

```dotenv
NAVER_CLIENT_ID=your-client-id
NAVER_CLIENT_SECRET=your-client-secret
```

서버에서 네이버 Maps Geocoding을 호출해 신규 어르신 주소를 좌표로 변환합니다. 키는 브라우저에 노출하지 않습니다. 기존 시연 어르신과 보호사는 가상 좌표를 사용합니다.

네이버 지도 API의 역할은 주소/위치/경로 처리입니다. 보호사의 실제 빈 일정과 자격은 기관이 별도로 보유·관리해야 합니다. 현재 매칭은 직선거리와 고정 이동 여유를 사용하며 Directions 기반 실제 이동 시간은 아직 연결하지 않았습니다.

공식 문서:
- [NAVER Maps API](https://api.ncloud-docs.com/docs/en/ainaverapi-maps-overview)
- [Ollama Chat API · structured output](https://docs.ollama.com/api/chat)

## 구조

- `server.mjs`: 로컬 HTTP 서버, 요청·동작·등록 API, 파일 저장
- `lib/scheduler.mjs`: 매칭, 충돌 검사, 상태 전이, 처리 이벤트
- `lib/integrations.mjs`: STT, Ollama 구조화 추출, 네이버 주소 검색
- `lib/seed.mjs`: 가상 어르신·보호사·요청
- `public/`: 반응형 관리 화면과 단일 마이크 어르신 화면
- `test/scheduler.test.mjs`: 핵심 매칭 및 상태 전이 테스트

## 실사용 전 남은 작업

기관 담당자와 서비스 시간·방문 범위·자동 배정 허용 조건을 확정해야 합니다. 의료 예약처럼 변경할 수 없는 시간, 응급 상황 등은 일반적인 빈 슬롯 탐색으로 해결하면 안 됩니다. 현재 LLM 프롬프트는 확인 대상으로 분류하도록 요청하지만 실제 데이터로 검증되지 않았으므로 실서비스 판단 수단으로 사용할 수 없습니다.

추가 운영 연동 범위는 실제 기관 일정/자격 연동, 다중 서버용 데이터베이스, 개인정보 동의/보존정책, 일정 취소/수정, 한국어 날짜 해석과 소음 환경 음성 인식 실기기 검증입니다. 다중 서버 운영, 실사용 배포, 보호사에게 외부 신청 전송은 현재 범위에 포함되지 않습니다.

## Expo Go · 보호사 가입과 근무 설정

`npm ci --prefix expo` 후 `npm run expo`를 실행하고 휴대폰의 Expo Go에서 QR을 읽으세요. 가입 시 희망 지역·요일·시간을 입력하고, **내 근무 설정**에서 수정할 수 있습니다. 자세한 실행 방법과 체험 범위는 [Expo Go 안내](docs/EXPO.md)에 정리했습니다.

## 실제 회원가입과 로그인

브라우저에서 `http://localhost:3000/`를 열면 실제 계정으로 가입·로그인할 수 있습니다. 가입 시 근무 조건이 함께 저장되며 보호사/사회복지사/어르신 기기의 API 권한을 분리했습니다. [계정 사용 및 기관 계정 발급 안내](docs/AUTH.md)를 참고하세요. 기존 체험 모드에서는 **실제 계정 로그인**을 눌러 전환합니다.
