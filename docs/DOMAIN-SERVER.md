# 구매한 도메인으로 이 PC에서 직접 운영

도메인을 입력하는 것만으로 보안이 보장되지는 않습니다. 이 실행 방식은 ngrok 대신 PC의 Caddy에서 HTTPS를 처리합니다. 도메인 구매 외 서버 소프트웨어 비용은 없지만 회선 제한·전기·운영 비용은 별개입니다. 자동 시작이나 서비스 등록은 하지 않습니다.

## 연결 전 준비

1. 공식 https://caddyserver.com/download 에서 Windows용 Caddy를 받고 실행 파일 위치를 확인합니다.
2. `deploy/domain.env.example`을 `.env.domain`으로 복사하고 `CLOVER_DOMAIN`에 실제 도메인만 입력합니다. 필요하면 `CADDY_PATH`에 실행 파일의 전체 경로를 적습니다. 키는 기존 `.env`에서 읽습니다.
3. 가비아 DNS에서 사용할 주소의 A 레코드를 이 PC가 사용하는 회선의 공인 IPv4 주소로 지정합니다. 사용하지 않는 AAAA 레코드가 있으면 다른 서버로 연결될 수 있으므로 확인합니다. ngrok 주소로 CNAME 연결하면 이 직접 연결 방식이 아닙니다.
4. 공유기에서 TCP 80·443만 이 PC로 전달하고 Windows 방화벽도 Caddy에 한해 허용합니다. 앱 3000, 음성 18000, AI 11435, 원격 데스크톱·공유 폴더 포트는 외부로 개방하지 않습니다. 이 코드는 공유기·방화벽을 자동 변경하지 않습니다.
5. 공유기 WAN 주소가 공인 주소와 다르거나 통신사가 인바운드 연결을 막으면 회선 설정부터 해결해야 합니다. 유동 IP 변경 시 DNS도 갱신해야 합니다.
6. 기존 앱 실행창에서 Ctrl+C로 종료하고 `Start-Domain.cmd`를 실행합니다. Caddy가 인증서를 발급한 뒤 `https://실제도메인/app/`을 엽니다. 종료는 Ctrl+C입니다. 인증서는 Caddy의 사용자 데이터 폴더에 보관되며 실행 중 자동 갱신됩니다.

`npm run start:domain -- --check`는 설정과 Caddy 구문만 확인하며, 외부 포트나 인증서 발급 성공을 확인하지는 않습니다. 도메인이 바뀌면 새 주소에서 로그인하고 네이버 등 연결 서비스의 허용 URL 및 앱 WebView 주소도 변경해야 합니다.

## 검증과 남은 운영 작업

휴대폰 Wi-Fi를 끄고 새 주소에 접속해 인증서, 로그인, 승인 대기 차단, 역할별 접근, 녹음, 로그아웃을 확인해야 실제 연결 완료입니다. 도메인을 모르는 상태에서는 이 검증을 할 수 없습니다.

앱에는 비밀번호 해시, 운영용 Secure/HttpOnly/SameSite 쿠키, 출처 제한, 역할·승인 검사, 로그인 시도 제한이 있습니다. 이번 보완은 HSTS, 프레임 삽입 차단, 마이크 자기 출처 제한, 교차 사이트 POST 차단, 요청 수신 제한 시간을 추가합니다. 녹음 처리 자체에는 60초 제한을 걸지 않고 요청 업로드에만 적용합니다.

현재 JSON 데이터와 보관 녹음은 별도 저장 암호화가 적용되지 않았습니다. PC 계정 보호, 디스크 암호화, 접근 권한, 백업 및 녹음 보관 기간 정책이 추가로 필요합니다. 현재 작업 폴더는 OneDrive 경로이므로 운영 저장소를 별도 폴더로 옮길지 확인해야 합니다. 이 변경은 데이터 이동·삭제나 BitLocker 설정을 자동 수행하지 않습니다. CLOVER_DATA_DIR을 빈 폴더로 바꾸면 계정도 빈 상태가 되므로 기존 데이터를 확인 없이 변경하지 마세요.

공인 주소로 직접 연결하면 PC에 외부 요청이 도달합니다. HTTPS는 전송을 보호하며 앱 취약점이나 PC 침해를 해결하지 않습니다. 실제 개인정보 운영 전 별도 보안 점검이 필요합니다. PC 종료·절전 시 서비스 및 안부 알림도 중단됩니다.

공식 자료: https://caddyserver.com/docs/automatic-https
