## 재현 가능한 기술 근거

`npm test`: 인증, 권한, 일정, 입력 경계, 음성 장애, 안부 등을 검증합니다. 보안 인증이나 실제 서비스 적합성 인증은 아닙니다.

`npm run evaluate:rubric`: 실제 모델 없이 시간 56건, 돌봄 안전 32건, 안부 16건을 재현합니다. 2026-10-02 실행 결과 104/104 통과, 위험 사례 18건 중 자동처리 0건입니다.

`node --env-file-if-exists=.env scripts/evaluate-rubric.mjs --live`: 기존 로컬 모델을 사용해 돌봄 32건도 추가 평가합니다. 2026-10-02 실행은 32/32 통과, p95 약 21.7초입니다. STT·실제 녹음은 포함하지 않습니다. 결과는 `artifacts/rubric-live-evaluation.md`와 JSON에 기록됩니다. 개별 실패·예외도 분모에 포함합니다.

현재 정답셋은 개발자가 작성한 합성 회귀 데이터입니다. 이 데이터에 맞춰 개선했으므로 독립 테스트셋이나 실제 사용자 정확도로 표현하면 안 됩니다. 시간 평가와 의도 평가는 별도이며 현재 LLM 평가는 돌봄 종류와 검토 여부를 측정합니다.

## 5분 시연 순서

1. (40초) 직원 화면에서 가입 승인 대기와 관리자 승인 권한 설명. 미승인 보호사의 로그인 차단을 가상 계정으로 확인.
2. (70초) 어르신이 “내일 오후 두 시에 밥 좀 차려줘”라고 새로 발화. 인식 문장·시간·돌봄 종류·배정 이유 확인. 실제 AI는 지연될 수 있음.
3. (50초) “내일 두 시쯤”처럼 모호한 표현 또는 “약 몇 알 먹어야 해?” 입력. 임의 확정 대신 담당자 검토로 이동하는 것을 확인.
4. (60초) 보호사 불가 사유 → 사회복지사 시간 먼저 선택 → 가능한 보호사만 선택 → 처리 기록 확인.
5. (40초) 마스킹 목록·상세정보·동의 폼·SOS를 가상 데이터로 설명. SOS는 119 자동 출동이 아님을 명시.
6. (40초) 평가 보고서의 통과 수, 실패 수, 지연, 합성 데이터 한계를 제시. 심사위원 자유 입력을 추가로 시험.

실제 개인정보 화면을 촬영하지 않습니다. 요청 실패를 정상 접수처럼 꾸미지 말고 이유와 담당자 조율 대안을 보여줍니다. 서버 장애 때는 SOS도 전송되지 않을 수 있으므로 전화·119 대체 경로를 설명합니다.

측정: 성공/전체, 도움 요청 횟수, 완료 시간 중앙값, 오류·중도 포기 수, 사회복지사 실제 작업시간, 요청당 직원 개입 횟수. 포기·장애 사례를 제외하지 않습니다. 음성 평가는 동의받은 녹음과 사람 전사 정답을 별도 보관하며 개발에 사용하지 않은 발화로 평가합니다.

## 확장·운영 가설

기관 단위 이용료 모델을 검토하되 금액·수익성은 미검증입니다. 기관당 직원 조율 시간 절감이 모델·서버·지원·교육 비용보다 큰지 확인해야 합니다. 현재 로컬 PC·무료 터널은 전원·회선·알림 제약이 있으며 상시 서비스 보장을 뜻하지 않습니다. 다른 기관을 수용하기 전에 기관 간 데이터 분리를 구현·검증해야 합니다.

## 이번 개인정보 보완의 범위

신규 가입과 직원의 어르신 등록에 기본 개인정보 수집·이용 확인을 요구합니다. 기록은 서버 시각과 문서 버전으로 저장하며 기존 회원에게 소급해 동의를 부여하지 않습니다. 이는 적법한 민감정보 처리·국외 이전·실명 확인의 완결을 의미하지 않습니다.

마스킹은 어르신 관리 목록의 시각적 노출을 줄입니다. 승인된 직원에게 전달되는 원본 API 데이터 자체를 익명화하지 않으며, 상세 화면과 다른 업무 화면에는 필요한 정보가 표시됩니다. 발표 시에는 가상 데이터만 사용하세요.
