## 확인과 일정 상태

`음성 해석 → draft(내용 확인) → 어르신 확인 → pending(수락 대기) / attention(조율 필요) → 보호사 수락 → confirmed(확정) → completed(완료)`

요청 내용 확인과 확정 일정 확인은 별도 기록이다. 확정 일정 변경은 변경 요청으로 남기며, 새 일정 재신청 후 보호사 수락이 다시 필요하다.

## 검증

- 자동 테스트 314개 통과: 역할·기관 격리, 보호사 비서 권한·타인 ID 변조·본인 근무 변경, 주간 범위·일정 종료 시각, 전체 조회 도구, 집계·페이지, 초안 확인·수정·취소, 변경안 재검사, 출석, 모델 반복 호출 중단, 기존 API 회귀 테스트.
- 보호사 비서: Chromium·WebKit에서 메뉴 진입·본인 일정 조회·관리자 도구 차단·근무 확인 후 변경을 검증했다. 설치된 Qwen3:4b에서도 보호사 범위 통계·주간 일정·근무 조회를 확인했다. 단일 상대 기간의 일정 조회는 한국 달력 기준을 적용하고 일정 답변은 저장된 시작·종료 시각으로 구성한다.
- 설치된 Qwen3:4b 실제 실행: 가상 데이터의 `get_statistics` 호출 후 ‘접수 3건, 미처리 1건, 완료 1건’ 응답을 확인했다. 단일 검증 소요 약 9.7초이며 동시 처리 성능이나 전체 답변 정확도 측정은 아니다.
- Chromium 계열 Edge와 Playwright WebKit: 비서 조회, 변경안 확인 전후, 보호사 시간표·수락, 어르신 확인·오른쪽 스와이프·일정 확인·변경 요청의 7개 흐름 통과. 가로 넘침 및 브라우저 오류 검사 포함.
- 웹·공통 모바일 번들 빌드, Android/iOS 프로젝트 동기화와 메타데이터·마이크 권한·번들 일치 검사.
- 결과와 화면: `output/feedback-implementation/`. WebKit 검증은 실제 iPhone Safari 기기 검증을 대신하지 않는다. 네이티브 검증은 APK/IPA 컴파일·실기기 테스트가 아니다.

## 확정되지 않은 운영 사항

회의에서 언급한 모델 교체·Bedrock/ZDR·국내 모델·STT 대안은 비교 후보이며 도입 확정 사항이 아니다. 현재 모델의 실험 결과를 전체 운영 정확도로 일반화하지 않는다. 실제 어르신 음성·잡음·운영 장비에서의 STT 정확도와 동시 처리 용량, 실기기 푸시, 공유 DB 전환, 기관 관리자·팀장 승인 계층, 데이터 보관·삭제 기간은 별도 확인이 필요하다. 기존 배정 기준은 유지하며 현장 기준으로 확정했다고 표시하지 않는다.
