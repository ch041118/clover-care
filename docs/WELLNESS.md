# 매일 저녁 안부 확인

기본 정책은 사용자 선택대로 **한국 시간 매일 19:00, 5분 간격 총 3회**입니다.

| 시간 | 동작 |
| --- | --- |
| 19:00 | 오늘 앱을 사용하지 않은 어르신에게 첫 안부 질문 |
| 19:05 | 아직 응답이 없으면 두 번째 질문 |
| 19:10 | 아직 응답이 없으면 세 번째 질문 |
| 19:15 | 여전히 응답이 없으면 사회복지사 확인 목록과 푸시로 알림 |

첫 문구는 “저녁은 드셨어요? 오늘 하루는 어떠셨나요? 편하게 안부를 들려주세요.”입니다. 이후에는 “잘 지내고 계신가요? 괜찮으시면 클로버에 짧게 답해 주세요.”로 묻습니다.

## 사용 흐름

- 어르신이 그날 앱을 직접 열거나 조작한 기록, 실제 돌봄 요청이 있으면 그날의 새 안부 확인을 생략합니다. 단순 서버 조회·자동 새로고침은 사용으로 세지 않습니다.
- 질문을 보낸 이후 앱이나 알림을 열기만 한 것은 답변이 아닙니다.
- 질문 중에만 어르신 화면에 **네, 잘 지내요** 버튼이 나타납니다. 한 번 누르면 확인 완료입니다. 기존 마이크로도 답할 수 있습니다.
- 마이크 답변은 STT로 전사합니다. 명확한 긍정 표현만 자동 완료하며, 부정·도움 요청·그 밖의 문장은 담당자가 확인하도록 올립니다. 일반 돌봄 예약을 잘못 생성하지 않습니다.
- 응답 이후 예약 중인 재알림을 취소합니다. 이미 푸시 공급자가 접수한 알림은 기기에 늦게 도착할 수 있습니다.
- 사회복지사 확인 목록에 올라간 뒤 늦게 답이 오면 이력을 유지합니다. 담당자가 연락 결과를 적어 **확인 완료**해야 목록에서 해결됩니다.
- 전송 실패·알림 권한 없음·기기 미등록은 **알림 전송 확인 필요**로 표시합니다. 이를 어르신 무응답으로 횟수에 포함하지 않습니다.
- 미해결 확인 건이 있으면 다음 날 같은 어르신에게 새 사건을 중복 생성하지 않습니다.

사회복지사 화면에서 **오늘의 안부**를 선택하세요. 시간과 총 횟수(1~5회)를 변경할 수 있고, 5분 간격은 고정입니다. 기존 진행 건은 시작 당시 정책을 유지합니다. 전체 안부 확인을 끄면 대기 재알림도 취소합니다.

## 바로 체험

웹 관리 화면 또는 앱 체험 모드에서:

1. **오늘의 안부 → 안부 확인 흐름 체험**을 선택합니다.
2. 어르신을 고르고 첫 알림을 체험합니다.
3. **5분 경과 체험**을 누를 때마다 다음 회차로 넘어갑니다.
4. 3회 알림 이후 한 번 더 진행하면 담당자 확인 대상이 됩니다.
5. **어르신 응답 화면 체험**에서 버튼으로 답하거나, 담당자 화면에서 연락 결과를 기록합니다.

체험은 실제 푸시를 보내지 않고 실제 어르신의 활동 시각도 변경하지 않습니다. 체험 모드가 앱을 닫은 동안 안부를 자동으로 확인하는 것처럼 표시하지 않습니다.

## 백그라운드 처리 방식

알림 시간 판단은 휴대폰 타이머가 아니라 **항상 실행되는 Node 서버**가 담당합니다. 서버가 15초마다 확인하므로 서버 처리 기준으로 최대 약 15초 오차가 있을 수 있습니다. 실제 기기의 알림 표시는 OS·네트워크·절전·알림 권한 상태에 따라 늦어질 수 있습니다.

`활동 기록 → 일별 확인 건 → 영속 발송 대기열 → FCM/APNs → 응답 또는 담당자 확인`

진행 회차와 대기열은 기존 `data/state.json`에 저장되어 재시작 후 유지됩니다. 푸시 서비스가 발송을 접수한 시각부터 5분을 기다립니다. 서버 중단 후 오래된 알림을 연속 발송하지 않도록 대기 알림은 5분 뒤 만료합니다. 저녁 시작 후 2시간이 지나면 새 질문을 늦은 밤에 발송하지 않고 담당자에게 처리 실패를 남깁니다.

발송 전 대기열 상태를 저장하며, 처리 중 서버가 종료되면 2분의 임대 기간 후 회복합니다. 푸시 네트워크 경계에서는 정확히 한 번 발송을 보장하지 않으며, 같은 확인 건의 collapse/tag 값으로 중복 표시를 줄입니다. 응답 저장은 멱등 처리됩니다. 현재 서버는 **단일 프로세스**용입니다. 여러 서버로 운영할 때는 트랜잭션 가능한 DB와 분산 작업 잠금으로 교체해야 합니다.

## 실제 기기 푸시 연결

현재 저장소에는 실제 Firebase/APNs 자격 증명이 없습니다. **실기기 수신 및 앱 종료 상태에서의 푸시는 아직 검증하지 않았습니다.** 서버를 인터넷에 공개하기 전에 기존 시제품에 없는 인증·역할별 권한·기관별 접근 제한을 추가해야 합니다. 푸시 토큰은 서버에만 저장하고 상태 조회에서는 제거합니다.

### Android

1. Firebase 프로젝트에 앱 ID `kr.clover.care`를 등록합니다.
2. 앱 설정 파일을 `android/app/google-services.json`에 넣습니다. 이 파일은 Git 및 소스 압축본에서 제외됩니다.
3. 서버용 서비스 계정 파일을 저장소 밖에 두고 `.env`의 `FCM_SERVICE_ACCOUNT_FILE`을 지정합니다. Firebase Cloud Messaging API 및 서비스 계정 발송 권한을 설정하세요.
4. 앱을 다시 빌드하고 서버 연결 모드로 설정합니다. 초기 설정의 **안부 및 담당자 확인 알림 받기**를 선택하고 OS 알림 권한을 허용합니다.
5. 기존 설치 앱에서는 담당자 화면 **오늘의 안부 → 이 기기 푸시 알림 연결**을 사용합니다. 어르신 기기는 로고를 4초 눌러 기기 설정을 다시 열 수 있습니다.

### iPhone

1. Apple Developer의 App ID에 Push Notifications를 활성화하고 Xcode의 Team/서명 프로파일을 설정합니다.
2. 프로젝트에는 AppDelegate 등록 콜백과 `App.entitlements`를 추가했습니다. Debug는 `development`, Release는 `production` 환경을 사용합니다.
3. 서버 밖에 보관한 APNs 인증 키 경로와 다음 환경 변수를 지정합니다.

```dotenv
APNS_KEY_FILE=C:/private/AuthKey_example.p8
APNS_KEY_ID=your-key-id
APNS_TEAM_ID=your-team-id
APNS_TOPIC=kr.clover.care
APNS_ENVIRONMENT=sandbox
```

TestFlight/Release 기기 토큰은 `APNS_ENVIRONMENT=production` 서버를 사용해야 합니다. 현재 한 서버에서는 한 APNs 환경을 사용하므로 개발·운영 토큰을 섞지 마세요. 이 구현에서 iPhone은 FCM이 아닌 APNs에 직접 발송합니다.

### 사회복지사 알림

사회복지사 모드로 설정한 실제 기기도 같은 서버에 푸시 토큰을 등록해야 합니다. 현재는 한 기관의 사회복지사 기기 전체에 일반 문구로 알리고, 상세 내용은 앱에서 확인합니다. 미등록/전송 실패여도 서버의 확인 목록은 유지됩니다. 브라우저 화면만 사용하는 경우 목록을 확인할 수 있지만 OS 푸시는 제공하지 않습니다.

기기를 다른 서버·사용자로 바꾸거나 알림을 끌 때 이전 서버의 기기 등록을 비활성화합니다. 이전 서버에 연결되지 않으면 설정 변경을 완료하지 않으며, 연결을 복구한 뒤 다시 시도해야 합니다.

## 관련 파일과 검증

- `lib/wellness.mjs`: 일별 상태, 활동, 응답, 재알림 정책, 담당자 처리
- `lib/wellness-worker.mjs`: 영속 발송 대기열과 중복 작업 방지
- `lib/push.mjs`: FCM HTTP v1 / APNs HTTP/2 서버 전송
- `mobile/notifications.js`: 기기 등록, 권한, 푸시 클릭, 응답 후 알림 정리
- `public/wellness-ui.js`: 담당자 안부 목록, 설정, 어르신 응답
- `test/wellness.test.mjs`: 시간 경계, 중복, 취소, 실패, 늦은 응답, 재시작 검사

자동 테스트는 총 45개입니다. 외부 푸시 발송은 모의 전송으로 검사했으며 실제 기기/계정 연결 테스트가 추가로 필요합니다.

공식 문서: [Capacitor Push Notifications](https://capacitorjs.com/docs/apis/push-notifications), [FCM HTTP v1](https://firebase.google.com/docs/cloud-messaging/send/v1-api), [APNs 인증](https://developer.apple.com/documentation/usernotifications/establishing-a-token-based-connection-to-apns)
