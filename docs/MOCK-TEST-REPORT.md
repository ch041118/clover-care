# 가상 데이터 기반 검증 — 2026-09-30

실제 회원·연락처·주소·운영 일정에서 데이터를 추출하지 않았다. 문장은 수작업으로 만든 가상 요청이며, 위치는 가상의 근접/원거리 좌표다. 회원과 일정 테스트는 메모리 또는 별도 임시 폴더에서 실행하고 종료 시 지운다. 실제 알림은 보내지 않는다.

## 데이터와 실행

| 파일 | 내용 | 개수 |
|---|---|---:|
| `test/fixtures/request-times.json` | 한국어 시각·날짜·기간·잘못된 숫자·변경/범위 표현 | 56 |
| `test/fixtures/wellness-replies.json` | 긍정·부정·불명확·도움이 필요한 안부 답변 | 16 |
| `test/fixtures/scheduling.json` | 거리·근무·충돌·계정·누락 데이터에 따른 배정 | 20 |
| `test/fixtures/voice-intents.json` | 돌봄 종류·부정문·복합 요청·담당자 확인 필요 표현 | 24 |

추가로 가상 어르신 20명·보호사 8명에게 80건을 연속 배정하고, 별도 HTTP 서버에서 음성 요청 6건을 로그인→인식 응답→보정→저장→계정별 조회까지 검증한다. 이 HTTP 테스트의 음성 인식과 AI 응답은 의도적으로 틀린 모크이며 마이크나 실제 음성 인식 정확도를 측정하지 않는다.

- `npm test`: 전체 자동 테스트.
- `npm run test:mock`: 가상 데이터 중심 테스트 120개.
- `npm run evaluate:voice`: 설치된 로컬 AI에 24개 가상 문장을 전달한다. `.env`의 로컬 AI가 실행 중이어야 한다. 운영 서버에 요청을 등록하지 않는다. 결과는 `artifacts/voice-evaluation.json`에 저장된다.

가상 문장을 추가할 때 기대하는 서비스와 담당자 확인 여부를 함께 기록한다. 명확한 요청에는 `review: false`를 지정해 모든 요청을 확인 대상으로 보내는 구현도 실패하게 한다.

## 발견하고 수정한 부분

첫 시간 데이터 50개 중 18개가 기대한 결과와 달랐다. `09:30`, `정오`, `오후 14시`, `한 시간 30분 후`, `삼십 분 뒤`, `100분 뒤`를 지원했다. `100분`·`십십분` 같은 잘못된 분 표기를 일부만 읽는 문제, 여러 기간 중 첫 번째만 선택하는 문제, 밤 12시의 날짜 경계를 임의로 정하는 문제도 수정했다. 범위·마감·변경 조건과 불명확한 시각은 담당자가 원문을 확인한다. 한국어 시각과 기간을 분리하고 한국 날짜 경계로 계산한다.

배정 시나리오 22개 중 처음 7개가 실패했다. 근무시간 누락·좌표 범위 오류·0분/음수 소요시간·확인 대기 요청을 배정 엔진 자체에서도 거부하도록 보완했다. 사회복지사가 직접 조율할 때도 정지된 계정의 보호사로 재배정할 수 없게 했다. 기존 30분 이동 여유와 가장 빠른 가능 일정 검색은 유지한다.

로컬 AI 첫 12개 문장 평가에서 6개가 기대와 달랐다. 일부 의료행위·긴급 확인 표현·시간 고정 예약·복합 요청을 일반 돌봄으로 자동 배정할 위험이 있었다. 원문에 근거한 추가 확인 규칙과 사유를 붙였다. 명확하게 제외한 서비스는 분류에서 빼서 “청소는 안 해도 되고 밥만” 같은 요청을 식사 도움으로 보정한다. 모델 자체가 다른 이유로 요구한 담당자 확인은 해제하지 않는다.

안부 답변 16개는 기존 규칙으로 모두 통과했다. 단순한 긍정만 자동 응답 완료로 처리하고, “괜찮긴 한데 숨쉬기가 힘들어요” 같은 답변은 담당자 확인으로 남긴다.

## 범위와 한계

전체 자동 테스트 213개와 최종 로컬 AI 문장 평가 24/24개가 통과했다. 명확한 일반 요청이 불필요하게 확인 대상으로 넘어가지 않는 조건도 포함한다. 로컬 AI 평가의 최종 개별 결과와 실행 시각은 `artifacts/voice-evaluation.json`을 참조한다. 이 작은 수작업 데이터셋의 통과율은 실제 사용자 전체에 대한 정확도가 아니며, 모델 학습이나 재학습을 수행한 것은 아니다.

음성 잡음·사투리·실제 휴대폰 마이크·카카오톡 권한·푸시 도착은 이번 텍스트/모크 검증에 포함하지 않는다. 인식하지 못하는 돌봄 종류와 복잡한 시간 조건은 확인 요청으로 남으므로 실제 사용 사례를 추가해 개선해야 한다. 운영 데이터와 기존 요청은 테스트 목적으로 변경하지 않는다.
